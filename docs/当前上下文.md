# 当前上下文

## 项目名称

- 中文名：模型舱
- 英文名/工程名：`ModelDock`
- 工程目录：`${YONYOU_WORKSPACE}/github/ModelDock`

## 已确定方向

1. 支持 Windows、Linux、macOS。
2. 后端尽可能完全使用 Go，核心不依赖 Python、Node.js、Docker 或 aria2。
3. 前端使用 Vue3、Vite、TypeScript、Ant Design Vue。
4. 桌面模式优先使用 Wails，直接打开独立窗口；同时保留浏览器服务模式和 CLI 模式。
5. 前端构建后通过 `go:embed` 嵌入 Go 可执行文件。
6. 使用 SQLite 保存模型清单、下载任务、运行配置和日志索引。
7. 模型文件由用户选择存储根目录，支持多个目录、切换、迁移、外置硬盘和 NAS。
8. 根据机器硬件和已安装运行时推荐模型，而不是只按模型名称推荐。

## 推荐系统必须考虑

- Apple Silicon：统一内存、Metal、MLX。
- NVIDIA：显存、CUDA、驱动版本。
- AMD：ROCm 或 DirectML。
- Intel：DirectML、oneAPI 和集成显卡内存。
- CPU：架构、AVX/NEON、系统内存和量化格式。
- 任务类型：对话、代码、视觉、图片、视频、音频、Embedding。
- 模型版本：FP16、8bit、INT8、Q8、Q5、Q4、MLX 等。

推荐结果要说明：推荐、可以运行、不建议、不可用，以及具体原因。

## 当前参考经验

之前在另一目录管理 `MiniMax-H3-Image-4bit` 时验证过以下需求：

- Hugging Face 大模型下载必须支持代理和断点续传。
- 多线程下载不能只看进程是否存在，要检测实际字节增长。
- 终端关闭会导致临时下载进程退出，正式工具应使用跨平台后台任务/服务管理。
- 下载完成后要校验完整文件清单，不能只看模型目录是否存在。
- MLX 模型不能直接当作 ComfyUI 权重使用，模型格式和运行时必须匹配。

旧实验目录仅作为实现参考，不属于 ModelDock 的运行目录：

`${TOOL_WORKSPACE}/minimax-h3-image-mlx`

## 下一步建议

1. 建立 Go 后端和 SQLite 数据层。
2. 建立模型 manifest 和兼容性评分结构。
3. 先实现 Go 原生下载器和任务状态机。
4. 再实现硬件探测和模型推荐。

## 已确认的首版取舍（2026-11-15）

1. 模型来源采用适配器设计，首版支持公开的 Hugging Face、ModelScope、Ollama 和本地目录；后续可新增来源，不把来源写死在核心业务中。
2. CLI、服务和桌面入口统一使用 `modeldock` 命令及产品名称 ModelDock。
3. 模型候选项采用社区常见的“模型名 + 量化版本 + 参数规模”表达方式；量化版本作为独立候选项。
4. 首版下载器必须支持公开模型的断点续传、分片并发、代理、失败重试、停滞检测和完整性校验。
5. 首版以公开模型为主，不做账号认证、私有仓库和 token 管理，也不做模型 revision 管理；来源的最新公开信息可以重新拉取更新。
6. 推荐系统首版使用可解释的规则评分，不要求自动 benchmark 或额外可信度体系。
7. Windows、Linux、macOS 都是首版构建和运行目标，不能只针对当前 macOS 开发。
8. 首版支持物理删除、模型迁移和去重；删除前需要明确显示影响范围，暂不引入回收站和复杂软删除流程。
9. 局域网访问和认证暂不纳入首版，默认服务仍只监听 `127.0.0.1`。
10. 首版同时提供完整 Web 界面、服务模式和 CLI；优先保证核心流程可用，再逐步补齐运行时自动安装和高级管理能力。

当前代码进度：已完成 Go 服务、SQLite、模型 manifest/任务 API、Hugging Face/ModelScope 公开搜索与清单、Ollama 模型列表导入、可恢复的 HTTP Range 下载、任务暂停/取消/继续、速度/剩余时间/失败分类、启动任务恢复、本机能力探测、基础规则推荐、模型存储目录配置和容量统计、分类热门目录、Vue3/TypeScript/Vite/Ant Design Vue 页面、本地模型扫描/纳入管理和 `search`/`info` CLI。Ollama 文本生成入口、MLX Worker、本地 GGUF 纯 Go 生成已接通；存储根目录迁移（复制后校验并更新索引）、模型文件完整性检查、模型物理删除和 ComfyUI 服务探测也已实现。ComfyUI 工作流执行和 Wails 原生桌面壳仍需继续实现。

下载任务现在以 SQLite 为状态来源：服务启动会将进程中断的任务改为可继续的暂停状态，继续操作复用 `.part` 文件；文件完成后逐项校验大小和 SHA-256，再写入模型可用路径。存储根目录会记录在线状态、总容量、可用容量和索引模型数量，移除目录只删除配置记录，不删除目录中的模型文件。

存储迁移通过目标目录副本执行，检查普通文件大小后才更新模型路径和默认下载根目录，来源文件会保留以便人工确认。模型文件删除只允许已纳入管理且位于已配置存储根目录内的模型；仅从索引移除时保留文件。

MLX 模型当前采用 ModelDock 托管 Worker 的兼容实现：Go 可以识别旧模型目录中的 `generate-image.sh` 或 `generate-video.sh`，调用项目自带的隔离环境并返回生成文件，不要求用户编写 Python。这个路径只用于兼容现有 `MiniMax-H3-Image-4bit` 和 `MiniMax-H3-MLX-4bit` 目录，不能作为应用发布时的运行时分发方式。正式应用将把 MLX Worker、启动器和依赖环境放在操作系统用户数据目录的 `ModelDock/runtimes` 下，模型目录只保存权重；首次使用时按平台、架构和运行时版本自动准备。Windows 显示 MLX 不支持，改走 Ollama、llama.cpp 或 Windows 原生适配器。

本地扫描默认使用当前配置的模型根目录，会递归识别模型根目录下的 GGUF、SafeTensors、MLX 和常见配置文件，并忽略 `.venv`、`site-packages` 等运行时依赖目录。

配置数据库放在操作系统用户配置目录，模型根目录由用户配置，可同时添加多个目录。扫描会把模型路径、格式、大小、可用性和扫描时间写入数据库，模型 manifest 不依赖某个用户的绝对路径。
扫描发现和纳入管理是两个状态；取消纳入只改变管理状态，不删除索引记录或用户模型文件，下一次扫描仍可重新选择纳入。
服务启动和页面打开仅读取 SQLite 索引，不会递归扫描模型目录。用户主动执行“扫描全部目录”时才重新检查文件、更新大小/格式/可用性/扫描时间；扫描未发现的既有本地模型会保留记录并标记不可用。
本地模型页面默认展示数据库里的已扫描模型信息；扫描是单独按钮和独立结果区。模型交互页面按模型能力收集文本和参考图片，后续 Agent 工作流可以在同一页面边界内扩展。

模型交互请求使用异步生成 Job：Go 服务立即返回任务 ID，后台运行 MLX、Ollama 或纯 Go 适配器，前端轮询阶段、消息和开始/结束时间。这样长时间的图片和视频生成不会占用一个浏览器长连接；页面以 Agent 式步骤展示当前阶段和计时。

服务重启会使内存中的生成 Job 丢失。前端加载本地会话时会把仍处于运行状态的 assistant 过程标记为“已停止”，保留原始提示词并提供“继续任务”操作；轮询任务状态失败时采用相同状态，避免历史消息永久显示运行中。

MLX 图片编辑调用中，输入图片和生成文件使用独立路径；生成 Job 只接受实际输出文件，并在返回页面前检查文件存在、不是目录且大小大于 0，避免出现“显示完成但结果图片破损或为空”。

模型交互页会同时展示总耗时和每个阶段耗时。MiniMax H3 Image 4bit 的现有 MLX 脚本采用固定六步、guidance 1 的采样配置，属于通用图像编辑能力，不能保证人脸身份和五官像素级保持；涉及换装或重绘主体时应在提示词中明确“保留脸部、发型、姿态和构图，只修改……”并接受量化模型的质量边界。

图片生成参数默认由模型项目提供：输出尺寸 1024x1024、采样步数 6、guidance 1、随机种子每次随机、提示词扩展关闭。模型交互页允许用户覆盖这些参数；固定 seed 可复现结果，提高 steps 通常会增加耗时，提示词扩展需要额外模型并会增加首次准备时间。ModelDock 通过 `H3_IMAGE_*` 环境变量与现有 MLX Worker 约定参数，旧 Worker 忽略未知设置仍可使用默认行为。

前端轮询生成任务时，如果服务重启导致内存中的 Job 消失，页面会停止计时并提示任务状态获取失败，不再无限显示运行中。当前 Job 仍是内存数据，服务重启会丢失任务；长期运行任务需要后续持久化 Job 和取消接口。

Ollama 已提供独立管理页面和 `/api/ollama` 配置接口。服务地址保存在 SQLite settings 表，默认 `http://127.0.0.1:11434`；页面可测试连接并查看 Ollama 已安装模型，模型交互调用使用该地址。
Ollama 模型可从该页面一键登记到 ModelDock 的模型索引，登记只保存模型名称和外部运行时引用，不复制 Ollama blob。
Ollama 模型登记后与本地扫描模型一样进入统一索引；由于文件由 Ollama 管理，索引读取时自动视为可用，并同时出现在本地模型页和模型交互选择器中。

所有普通 HTTP JSON 接口统一使用 `success`、`data`、`errorMsg`、`error` 四字段 envelope。Go 服务在 API 出口统一包装成功和 `http.Error` 错误响应，前端 `services/api.ts` 统一解包；二进制模型产物下载和静态资源保持原始响应。

模型交互页面采用连续聊天工作区。前端以会话 ID 保存消息历史到浏览器本地，生成请求携带完整消息列表；Go 后端记录当前进程内的会话并将 Ollama 请求转换为 `/api/chat`，因此连续追问会保留上下文。MLX/图片任务仍按单次生成处理，但统一显示聊天结果和 Agent 执行时间线。后续如需跨设备或服务重启保留会话，需要将 Conversations 持久化到 SQLite。

模型交互工作区采用桌面客户端式固定壳层：左侧导航和顶部栏固定，只有右侧内容区域滚动。assistant 消息正文使用安全 Markdown 渲染，保留“复制 Markdown 源码”入口；每次生成的分析、规划、加载、执行和测试步骤嵌入该 assistant 消息并默认在运行中展开、成功后收起、失败时保持展开。输入区采用悬浮编辑器样式，参数面板根据文本、图片、视频、音频能力切换，未接通的运行时参数明确提示由对应运行时处理。

历史对话索引保存在浏览器本地，用户可以从列表直接切换、重命名或删除会话；系统不限制保留数量，删除会同时清理该会话的消息缓存。模型交互选择器保留全部登记模型，`available=false` 的记录显示为禁用状态，可用模型保持主题正文色并可正常选择；下拉浮层也使用主题变量，避免浅色背景上的灰色文字影响辨识。

每次用户发送提示词都会创建独立的 assistant 过程消息，执行阶段和耗时只显示在该消息下面；右侧不再承担完整执行时间线，只保留当前运行摘要，避免历史过程和当前任务混在一起。主题页提供浅色、暗色和水墨、朱砂、青瓷、竹影等中国风配色，主题变量同时控制滚动条、工作区、边框和侧栏颜色，并保存在浏览器本地。

执行过程卡片的背景、边框、时间线和状态图标统一使用主题变量。运行中只在当前阶段显示阶段耗时，顶部“执行过程”标题保持简洁的运行状态；任务完成或失败后，标题显示本次运行最终总耗时。

模型交互输入区采用统一编辑器容器：附件按钮、文本输入、发送/停止按钮共享主题背景、边框和圆角，输入框透明融入容器，聚焦时显示主题强调色，避免控件之间出现割裂的白色块。

交互页将用户最近一次可用的模型 ID 保存到浏览器本地。再次打开页面时优先恢复该模型，只有模型被移除或不可用时才选择其他可用模型。输入区的附件、发送和停止操作使用紧凑图标按钮，并通过标题提供操作提示。

输入区的附件和发送/停止按钮位于输入框容器内部，分别固定在左右两侧并垂直居中；文本区域通过内边距避让两侧控件，保持连续编辑器的视觉和操作关系。

MLX 运行脚本选择以模型任务能力为准：通用 `MiniMax-H3-MLX-4bit` 不再因为名称包含 `h3-mlx` 被误判为视频，任务标注为图片时使用图片脚本，标注为视频时才使用视频脚本。交互前端会根据 Job 当前 phase 补齐缺失或异常的步骤状态，避免出现总状态运行中但所有步骤显示等待执行。

Agent 步骤耗时依赖页面任务计时器刷新；当前步骤每秒更新显示，运行时未返回步骤开始时间时使用任务整体开始时间计算，避免执行生成一直显示 `00:00`。

存储设置页同时管理模型目录和运行时目录。运行时目录通过 `/api/runtime` 持久化到 SQLite settings，默认使用操作系统用户配置目录下的 `ModelDock/runtimes`；服务启动会自动创建目录，页面可修改位置并显示 MLX、Ollama、llama.cpp、ComfyUI 子目录是否已准备。运行时安装包后续以独立的、带校验清单的包写入该目录，普通用户不需要手动复制脚本或 Python 环境。

开发服务统一使用 `scripts/modeldock-dev.sh` 管理，支持 `start`、`stop`、`restart`、`status`，默认监听 `127.0.0.1:8787`，PID、日志和临时开发二进制放在被忽略的 `.modeldock-dev` 目录，避免多个手工启动的服务同时运行。

全站 UI 使用统一间距变量和组件间距规则：页面标题与内容、提示框与列表、分割线与卡片、卡片头/体/操作栏、按钮和标签之间保持固定节奏；模型路径等长文本限制行高并断行，避免内容挤压操作区。

模型交互页的历史对话使用浏览器本地索引维护：每个会话以首条提示词作为主题，保存更新时间和消息上下文，右侧历史对话卡片支持切换和新建。运行参数、复选框、选择框、发送按钮和输入区都使用主题变量，暗色模式不再出现黑色数值或突兀的纯蓝操作按钮。

MLX 项目脚本的执行策略（兼容模式）：macOS/Linux 构建在非 Windows 文件中通过 `bash` 启动旧模型目录中的脚本，Go 负责参数、环境变量、超时和输出文件检查；Windows 构建不会尝试调用 `.sh`，因为 MLX 依赖 Apple Silicon/Metal，统一返回不支持提示并由 Ollama、llama.cpp 或其他 Windows 适配器承接。发布版应优先从 `ModelDock/runtimes` 查找已安装的运行时，旧模型目录脚本只用于迁移和兼容。MiniMax H3 视频脚本使用 Bash 命令数组拼接可选图片参数，避免 `set -u` 下空数组展开导致纯文本生视频失败。

推理采用可插拔适配器，但配置对用户隐藏：ModelDock 根据模型格式、任务类型和本机能力自动选择纯 Go、Ollama、llama.cpp 或 MLX 适配器，并返回“可直接运行、需要准备组件、暂不支持”的运行方案。用户不需要手动填写运行时路径；后续由 ModelDock 自动下载或初始化适配器。

纯 Go 首个推理适配器采用 MIT 许可的 `github.com/ThiraSoft/golem`。已接入 GGUF 文本生成，并验证 Qwen3 0.6B Q2_K 端到端加载和生成。当前适配架构为 Gemma 4、Qwen3、Qwen3.5/3.8；Windows 主程序可构建，但该依赖的当前 mmap/Vulkan 源码未通过 Windows 编译，因此 Windows 运行方案应显示暂不支持，不能误报可运行。SafeTensors/MLX 图片与视频生成仍需后续接入对应 Go 实现。
