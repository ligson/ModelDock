# 当前上下文

## 项目名称

- 中文名：模型舱
- 英文名/工程名：`ModelDock`
- 工程目录：`${YONYOU_WORKSPACE}/github/ModelDock`

## 已确定方向

1. 支持 Windows、Linux、macOS。
2. 后端尽可能完全使用 Go，核心不依赖 Python、Node.js、Docker 或 aria2。
3. 前端使用 Vue3、Vite、TypeScript、Ant Design Vue。
4. 桌面模式优先使用 Wails，直接打开独立窗口；同时保留浏览器服务模式和 CLI 模式。
5. 前端构建后通过 `go:embed` 嵌入 Go 可执行文件。
6. 使用 SQLite 保存模型清单、下载任务、运行配置和日志索引。
7. 模型文件由用户选择存储根目录，支持多个目录、切换、迁移、外置硬盘和 NAS。
8. 根据机器硬件和已安装运行时推荐模型，而不是只按模型名称推荐。

## 推荐系统必须考虑

- Apple Silicon：统一内存、Metal、MLX。
- NVIDIA：显存、CUDA、驱动版本。
- AMD：ROCm 或 DirectML。
- Intel：DirectML、oneAPI 和集成显卡内存。
- CPU：架构、AVX/NEON、系统内存和量化格式。
- 任务类型：对话、代码、视觉、图片、视频、音频、Embedding。
- 模型版本：FP16、8bit、INT8、Q8、Q5、Q4、MLX 等。

推荐结果要说明：推荐、可以运行、不建议、不可用，以及具体原因。

## 当前参考经验

之前在另一目录管理 `MiniMax-H3-Image-4bit` 时验证过以下需求：

- Hugging Face 大模型下载必须支持代理和断点续传。
- 多线程下载不能只看进程是否存在，要检测实际字节增长。
- 终端关闭会导致临时下载进程退出，正式工具应使用跨平台后台任务/服务管理。
- 下载完成后要校验完整文件清单，不能只看模型目录是否存在。
- MLX 模型不能直接当作 ComfyUI 权重使用，模型格式和运行时必须匹配。

旧实验目录仅作为实现参考，不属于 ModelDock 的运行目录：

`${TOOL_WORKSPACE}/minimax-h3-image-mlx`
